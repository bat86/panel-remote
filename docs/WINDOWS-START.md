# Первый раз на Windows: как запускать и допиливать

Короткая инструкция без предположения, что ты уже писал под Windows.

## Если совсем коротко

1. Поставь **Git для Windows**, **.NET 8 SDK** и **Visual Studio 2022 Community** (набор компонентов «.NET desktop development»).
2. Склонируй репозиторий и зайди в папку.
3. Закрой старую версию «Пульта доски» в трее (иначе новая сборка просто покажет старое окно).
4. Запусти `dev-run.cmd` — он соберёт свежий EXE и откроет его в портативном режиме.
5. Правишь код → снова `dev-run.cmd` → проверяешь.
6. Коммитишь и пушишь.

```bat
git clone https://github.com/bat86/panel-remote.git
cd panel-remote
dev-run.cmd
```

## 1. Что установить

| Что | Зачем | Ссылка |

| Git for Windows | скачать/запушить репозиторий | https://git-scm.com/download/win |

В установщике Visual Studio выбери набор компонентов **«.NET desktop development» / «Разработка классических приложений .NET»**. Остальное можно не ставить.

Проверка после установки — открой **Windows Terminal** или **PowerShell**:

```powershell
git --version
dotnet --version
```

`dotnet --version` должен начинаться с `8.`.

> .NET на компьютер учителя ставить не нужно. Он нужен только тебе для сборки. Готовый EXE — self-contained.


Репозиторий приватный. Git откроет окно входа GitHub — войди под `bat86` и разреши доступ. Пароль/токен никуда в код не вставляй.

## 3. Запустить свежую сборку

### Вариант А — одной командой (проще)

```bat
dev-run.cmd
```

Скрипт:

1. проверяет ABI-структуры;
2. собирает `artifacts\PanelRemote\PanelRemote.exe`;
3. запускает его с `--portable`.

`--portable` — важно. Без него приложение может тихо установиться в профиль и прописаться в автозапуск. Для разработки нам это не нужно.

### Вариант Б — Visual Studio

1. Открой `PanelRemote.sln`.
2. Убедись, что выбран профиль запуска **PanelRemote (portable)**.
3. Нажми **F5**.

### Вариант В — вручную

```bat
build.cmd
artifacts\PanelRemote\PanelRemote.exe --portable
```

> **Если открылось старое окно:** в трее уже работает установленная версия. Кликни по её иконке → «Выход», затем запускай новую сборку снова. Два экземпляра приложение не запускает специально.

## 4. Как менять код

Открой `PanelRemote.sln` в Visual Studio. Основные места:

| Что менять | Файл |
|---|---|
| Тексты, размеры, расположение 7 кнопок | `src/PanelRemote/MainWindow.xaml` |
| Внешний вид одной большой кнопки | `src/PanelRemote/Controls/ActionTile.xaml` |
| Логика экрана / режимы / детект панели | `src/PanelRemote/Services/DisplayService.cs` |
| Логика звука / выбор устройства | `src/PanelRemote/Services/AudioService.cs` |
| Восстановление после reconnect, диагностика | `src/PanelRemote/Services/AppController.cs` |
| Установка, автозапуск, ярлыки | `src/PanelRemote/Services/InstallService.cs` |
| Win32/COM-структуры | `src/PanelRemote/Interop/*.cs` |

После правки:

1. Закрой запущенное приложение (трей → «Выход»).
2. Запусти `dev-run.cmd` или F5.
3. Проверь на панели/в Windows.
4. Посмотри журнал, если что-то не так (ниже).

### Что не надо трогать без причины

- `src/PanelRemote/Interop/DisplayConfigNative.cs` — там выверенные флаги CCD.
- `src/PanelRemote/Interop/AudioNative.cs` — там размеры COM-структур и порядок методов `IPolicyConfig`.
- `artifacts/` — это локальная сборка, в git её нет.
- Не добавляй NuGet-пакеты «на всякий случай».

Перед правками ABI-кода прочитай `AGENTS.md` — там список уже пойманных ловушек.

## 5. Где смотреть ошибку

### Журнал приложения

Нажми `Win+R`, вставь:

```text
%LOCALAPPDATA%\PanelRemote\logs
```

Открой последний `panel-ГГГГММДД.log`. В нём:

- какая панель найдена и как она определилась;
- какой режим применился;
- какие аудиоустройства найдены;
- полный stack trace, если было исключение.

Из самого приложения: «ДИАГНОСТИКА» → «ОТКРЫТЬ ЖУРНАЛ».

### Если приложение не запускается

1. Посмотри, есть ли свежий лог в папке выше.
2. Запусти из PowerShell и дождись завершения, чтобы увидеть код возврата:

```powershell
$p = Start-Process -FilePath ".\artifacts\PanelRemote\PanelRemote.exe" `
  -ArgumentList "--portable" -PassThru -Wait
"ExitCode: $($p.ExitCode)"
```

3. Посмотри **Просмотр событий Windows** → «Журналы Windows» → «Приложение» → ошибки `PanelRemote` / `.NET Runtime`.
4. Если ошибка при сборке — скопируй **весь красный текст** из терминала, а не только последнюю строку.

### Если чёрный экран

1. Нажми «ДИАГНОСТИКА» — она заново применяет режим и тестовый звук.
2. Открой журнал.
3. Проверь на панели кнопку источника `HDMI` / `Source` / `Input`.
4. Запиши модель панели, тип кабеля, версию Windows (`winver`).

### Если нет звука

1. Нажми «ЗВУК НА ПАНЕЛЬ».
2. Проверь, что в Windows выбрано устройство с `HDMI` / `NVIDIA` / `AMD` / `Display Audio`.
3. Проверь громкость и mute на самой панели.
4. Приложи журнал — там видно, какое устройство выбрано и был ли `SetDefaultEndpoint` успешным.

## 6. Как закоммитить и запушить

Совсем коротко:

- **репозиторий** — папка проекта с историей изменений;
- **commit** — сохранить изменения у себя;
- **push** — отправить их на GitHub;
- **pull** — забрать свежее с GitHub.

Не редактируй код прямо на сайте GitHub в браузере: там легко сломать сборку и не видно ошибок компилятора.

Перед работой всегда забирай свежее:

```powershell
git pull
```

После проверки:

```powershell
git status
git diff
git add .
git commit -m "fix: короткое описание что исправил"
git push
```

После пуша GitHub Actions сам соберёт проект на Windows и Linux. Смотреть: https://github.com/bat86/panel-remote/actions

### Если сломал и хочешь откатить

Убрать незакоммиченные изменения:

```powershell
git restore .
```

Откатить локальные коммиты к версии с GitHub:

```powershell
git fetch origin
git reset --hard origin/main
```

`git reset --hard` удаляет незакоммиченные изменения. Если не уверен — сначала сделай копию папки.

## 7. Как просить другой чат/AI

### Если чат умеет работать с репозиторием

Дай ему ссылку на репозиторий и скажи:

> Прочитай `AGENTS.md`, `docs/HANDOFF.md`, `docs/TEST-STATUS.md` и `docs/TECHNICAL.md`. Работай в этом репозитории. Не меняй стек, не добавляй NuGet, не коммить `artifacts/`. Сначала объясни причину, потом сделай минимальный дифф.

### Если чат НЕ видит репозиторий

Приложи файлы:

- `AGENTS.md`;
- `docs/HANDOFF.md`;
- `docs/TEST-STATUS.md`;
- файл, который правишь;
- последний лог `panel-*.log`;
- при необходимости — скриншот ошибки.

И вставь шаблон из [AI-CONTEXT-PROMPT.md](AI-CONTEXT-PROMPT.md). Заполни только поля в квадратных скобках.

### Главное правило

Не пиши «не работает, почини». Пиши:

- что нажал;
- что ожидал;
- что произошло;
- что уже проверил;
- полный текст ошибки/лог;
- версию Windows, панель и кабель.

Чем конкретнее ввод — тем меньше AI будет гадать.

- [ ] `git status` чистый, `artifacts/` не в коммите.

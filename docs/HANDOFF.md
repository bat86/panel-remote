# Handoff — «Пульт доски»

Дата передачи: 2026-11-08. Предыдущая работа велась в Linux-окружении без физической Windows-машины и без интерактивной панели.

## Коротко

Сделан Windows-приложение на C#/WPF (.NET 8, win-x64) для переключения изображения и звука между компьютером преподавателя и интерактивной панелью. Реализованы 4 режима экрана, 2 кнопки звука, сохранение выбора, восстановление после переподключения HDMI, диагностика с тестовым звуком, трей, глобальные F8/F9, установка без администратора и журналирование.

Главный результат:

```
artifacts/PanelRemote/PanelRemote.exe
artifacts/PanelRemote-win-x64.zip
```

Артефакты локальные и **не входят в git** (`.gitignore`). Исходники, тесты, документация и макеты — в репозитории.

## Что реализовано

### Экран

- Поиск панели через Windows CCD: `QueryDisplayConfig`, `DisplayConfigGetDeviceInfo`, `SetDisplayConfig`.
- Кандидат в панель — внешний target (HDMI/DisplayPort/USB-C и др.), не внутренний экран ноутбука. Учитываются тип разъёма, имя, активность, признак основного экрана.
- Компьютерный экран — внутренний экран ноутбука, иначе основной монитор, исключая панель.
- 4 режима:
  - «Только компьютер» — `SDC_TOPOLOGY_INTERNAL`;
  - «Дублировать» — `SDC_TOPOLOGY_CLONE`;
  - «Расширить» — `SDC_TOPOLOGY_EXTEND`;
  - «Только панель» — `SDC_TOPOLOGY_EXTERNAL`.
- После каждого переключения состояние перечитывается и проверяется: активна ли панель, активен ли компьютер, действительно ли это clone/extend.
- Если topology не сработала (часто на стационарных ПК), используется fallback: из `QDC_ALL_PATHS` выбираются нужные пути, modeInfo переиндексируются, экран ставится в `(0,0)`, вызывается `SetDisplayConfig` с `SDC_USE_SUPPLIED_DISPLAY_CONFIG`.
- Для duplicate ищется общий режим через `EnumDisplaySettings` и `ChangeDisplaySettingsEx`; если Windows уже выбрала общий режим, он сохраняется.
- При переподключении панели повтор применяется дважды с паузой — это лечит часть зависших HDMI handshake.

### Звук

- `MMDeviceEnumerator` / `IMMDevice` / `IPropertyStore` — перечисление активных render-устройств.
- Определение панели по имени HDMI/DisplayPort/Display Audio, бренду панели и штрафу за имя монитора компьютера.
- `IPolicyConfig.SetDefaultEndpoint` для `eConsole`, `eMultimedia`, `eCommunications`. API недокументированный, но работает без администратора.
- Проверка фактического default endpoint после переключения.
- Сохранение ID выбранного устройства панели/компьютера.
- Тестовый WAV (два тона) через `winmm.PlaySound(SND_MEMORY|SND_ASYNC)`.

### Состояние и восстановление

- `SettingsStore` — JSON в `%LOCALAPPDATA%\PanelRemote\settings.json`, атомарная запись.
- `AppController` следит за переходом «панель отсутствует → появилась» и применяет `LastDisplayMode` + `LastAudioTarget`.
- При отключении панели приложение остаётся работоспособным: статус «панель не подключена», кнопки доступны, на экране инструкция.
- При ошибке переключения показывается крупное уведомление, в статусе остаётся фактическое состояние.

### Диагностика

- Всегда заново применяет режим и повторяет HDMI handshake.
- Отправляет тестовый звук на текущий выход.
- Крупно объясняет:
  - «Кабель не подключён»;
  - «Панель не определена»;
  - «Изображение есть, звук на компьютере»;
  - «Панель подключена, но изображения нет»;
  - «Windows не видит динамики панели».
- Кнопка «Исправить звук и экран» переводит режим в duplicate (если он не был extend/panel-only) и принудительно переключает звук на панель.
- Журнал открывается из оверлея.

### Инсталляция и сопровождение

- Самопрописка при первом запуске в `%LOCALAPPDATA%\Programs\PanelRemote`.
- HKCU Run с `--tray`, ярлыки на рабочем столе и в «Пуск».
- `--install --silent`, `--uninstall`, `--portable`.
- Один экземпляр: mutex + broadcast-сообщение «показать окно».
- Трей-иконка, меню «Открыть / Поверх всех окон / Выход».
- Глобальные F8/F9 (с обработкой занятости клавиш).
- Логи в `%LOCALAPPDATA%\PanelRemote\logs`, ротация.

### Интерфейс

- 7 огромных кнопок, `MinHeight=150`, `FontSize=43` DIP (= 32,25 pt), крупные emoji-иконки.
- 3×3 сетка: 3 кнопки экрана, 3 кнопки звука/панели, широкая «Диагностика».
- Главная кнопка «Дублировать» выделена синим/свечением; активное состояние — зелёное.
- Нижний статус: текущий режим + разрешение, текущее аудиоустройство.
- Верхняя полоса: подключена ли панель, имя и разъём.
- Только русский UI, без меню и настроек на первом уровне.
- Макеты: [preview/main-screen.png](../preview/main-screen.png), [preview/diagnostics.png](../preview/diagnostics.png). Это **макеты**, не снимок WPF.

## Как это проверялось

### Что реально выполнено

1. **Сборка WPF на Linux под Windows.**
   - `dotnet build PanelRemote.sln -c Release` — 0 ошибок, 0 предупреждений.
   - `dotnet publish ... -r win-x64 --self-contained true -p:PublishSingleFile=true ...` — успешно.
   - Размер EXE: `66 491 297` байт.
   - SHA-256: `7256cdef88e0badfbcc471f30a78ff9293cdf34c2103aa1623ec313ea89d5b23`.
3. **ABI-тест `tests/InteropLayoutChecks`.**
   - Проверяет размеры `DISPLAYCONFIG_*`, `DEVMODE`, `DISPLAY_DEVICE`, `PROPERTYKEY`, `PROPVARIANT` и значения флагов CCD.
   - Изначально выявил две реальные ошибки:
     - `PROPVARIANT` был 16 байт вместо 24 — native `IPropertyStore.GetValue`/`PropVariantClear` могли испортить память;
     - флаги CCD были сдвинуты (`SDC_SAVE_TO_DATABASE` и др.).
   - После исправлений тест проходит.
4. **Тихая установка/удаление в Wine (на финальном Windows CI EXE).**
   - `PanelRemote.exe --install --silent` копирует EXE, пишет HKCU Run, создаёт ярлыки.
   - `--uninstall` удаляет автозапуск, ярлыки и папку.
   - Проверено именно с `artifacts/PanelRemote/PanelRemote.exe` из Windows CI.
   - Первый прогон ярлыков падал из-за Wine: `Desktop` был symlink на `/home/vasily/Рабочий стол` вне sandbox. После замены на записываемую папку ярлыки создались. Это ограничение Wine, не Windows.
5. **Проверка решения о UI.**
   - Собран HTML-макет 1366×728 по тем же размерам/цветам/сетке; проверены переносы длинных подписей и высота кнопок.
6. **Структура и метаданные.**
   - EXE — PE32+ x86-64, GUI subsystem, иконка присутствует.

### Что не проверено

- Запуск WPF на настоящей Windows (в Wine WPF падает на `MS.Internal.FontCache.Util`, это известное ограничение окружения).
- Реальное переключение CCD на Windows: топологии, clone, общий режим, HDMI handshake, стационарный ПК.
- Реальная смена default audio через `IPolicyConfig` на Windows 10/11.
- Реакция на физическое выдёргивание HDMI и авто-восстановление.
- Автозапуск после перезагрузки Windows.
- DPI 125%/150%, 1366×768, реальная панель.
- SmartScreen/антивирус и подпись.

## Известные ограничения и риски

1. **Физический чёрный экран нельзя достоверно определить через Windows API.** Если ОС считает путь активным, приложение не знает, что на панели нет картинки. Поэтому диагностика всегда повторно применяет режим, а reconnect делает двойной проход. Это лучшее, что можно сделать без обратной связи от панели.
2. **Несколько внешних дисплеев.** Эвристика «панель» может ошибиться, особенно при двух одинаковых HDMI-мониторах. В логах есть все кандидаты.
3. **Звук панели по USB без узнаваемого имени** может не связаться с дисплеем. Приложение не будет вслепую переключать на случайное устройство.
4. **`IPolicyConfig` — недокументированный API.** На Win10/11 он распространён, но может измениться.
5. **WPF-интерфейс проверен только компиляцией и макетом.** Нужен живой прогон.
6. **EXE не подписан.** SmartScreen может предупредить; для школы нужна подпись.
7. **1366×768 при 125%** — тесно; целевое разрешение 1920×1080.

## Как продолжать

### Сборка

Windows:

```bat
build.cmd
```

Linux (кросс-сборка):

```bash
./scripts/build-release.sh
```

Оба варианта сначала запускают ABI-тест. Результат — `artifacts/PanelRemote/PanelRemote.exe` (не коммитится).

### Проверка на железе

1. Windows 10/11 x64, обычный пользователь.
2. Запустить `PanelRemote.exe`, проверить отсутствие UAC.
3. Подключить панель HDMI.
4. Пройти [TEST-CHECKLIST.md](TEST-CHECKLIST.md).
5. Результаты и логи записать в [TEST-STATUS.md](TEST-STATUS.md).
6. При ошибке CCD/Core Audio приложить `%LOCALAPPDATA%\PanelRemote\logs\panel-*.log` и конфигурацию дисплеев.

### Безопасные места для правок

- Тексты/размеры кнопок — `MainWindow.xaml`, `Controls/ActionTile.xaml`.
- Логика режимов — `Services/DisplayService.cs`.
- Эвристика звука — `Services/AudioService.cs` (`ScorePanelCandidate`).
- Сценарии восстановления/диагностики — `Services/AppController.cs`.
- Установка/ярлыки — `Services/InstallService.cs`.

### Не делать без проверки

- Не менять вручную размеры native-структур и флаги CCD, не прогоняя `tests/InteropLayoutChecks`.
- Не добавлять `SDC_SAVE_TO_DATABASE` к topology-вызовам.
- Не менять порядок методов `IPolicyConfig`.
- Не коммитить `artifacts/`, `bin/`, `obj/`, `*.exe`, `*.zip`.
- Не переписывать UI на «удобный» без сохранения 7 огромных кнопок и русского языка.
